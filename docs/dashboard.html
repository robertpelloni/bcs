BTK Project Dashboard

One page for the whole BCS/BTK framework: every module, tool, language port, test suite, and workflow — grouped by value, highest first. This repo is a C++ framework, not a web app: this page is a static status board (no server). The product web dashboard (OmniDash) lives in the bqt submodule.

1 · Status & how to run

Build everything ⓘ

powershell -File scripts\build-all.ps1 — one command. Fast check without compiling: scripts\build-all.ps1 -CheckOnly.

Run the demo entry point

start.bat runs the Go port (ports\go) and prints “BCS Framework – Go Port Initialization”. The C++ framework is a library — downstream apps run it, not this repo.

Run the tests ⓘ

Configure with -DBUILD_TESTS=ON, then ctest --test-dir build -C Release --output-on-failure.

2 · Framework modules (C++, src/)

BtkCore highest value

Object model, signals/slots, threading, IO, timers, properties. Everything else stands on this. Header: <btkcore.h>.

BtkGui highest value

Widgets, painting, input, windowing, focus — plus multi-user ownership, the feature no rival framework has. Header: <btkgui.h>.

BtkNetwork

TCP/UDP sockets, HTTP, SSL/TLS, DNS, proxies. Header: <btknetwork.h>.

BtkMultimedia

Audio, video, camera, media playback. Header: <btkmultimedia.h>.

BtkSql

Database access with driver plugins (SQLite, ODBC; PostgreSQL/MySQL when SDKs are present). Header: <btksql.h>.

BtkWebKit

Embedded web browser engine. Header: <btkwebkit.h>.

BtkSvg · BtkOpenGL · BtkVulkan

SVG rendering; OpenGL rendering; Vulkan rendering (needs the Vulkan SDK ≥ 1.2.170 — not present on this machine, so it is skipped at configure time).

BtkXml · BtkXmlPatterns

DOM/SAX XML, stream readers/writers; XQuery, XPath, schema validation.

BML declarative UI ⓘ in revival

Declarative UI runtime (src/declarative) + script engine (src/script). See HANDOFF.md for the current frontier.

7 · Known gaps (honest list)

No system-tray app ⓘ

Nothing long-running ships in this repo, so there is no tray icon and no Quit-servers menu. By design, not by omission.

Old build tree is path-stale

build-vs2019 was configured when the repo lived at …\workspace\btk. Its binaries still run; rebuilding needs a fresh configure (build/). The old tree is left untouched.

Submodule pins drifted

All three submodules sit on different commits than recorded. Kept as-is — advancing a pin needs a build decision, see TODO.md.
